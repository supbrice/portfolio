Network Infrastructure Upgrade — CPS

A UniFi network for Computer Plus Solutions: gateway, PoE switching, and separate zones for staff, guests, and operational technology.

Problem

Staff PCs, guest access, and OT — digital signage, signals, and fleet tracking — shared a flat or poorly segmented LAN. Cameras and access points needed reliable PoE. Vendor-hosted OT needed a way out without a path into corporate traffic.

What I built

  • UniFi gateway with NAT, firewall, DHCP, and QoS.
  • Managed Layer 2/3 PoE switches and a UniFi Protect zone.
  • VLAN plan for corporate, public, OT, Protect, and management.
  • Troubleshooting write-ups for DNS, DHCP, VLAN, vendor path, and Layer 2 adoption, plus Python and PowerShell validation scripts.

Technologies

  • UniFi
  • VLAN
  • DNS
  • DHCP
  • NAT
  • QoS
  • PoE
  • Python
  • PowerShell

Key concepts

Deny inter-VLAN by default, then allow only what a zone needs. OT stays off corporate. Configs in the repo are sanitized examples, not a controller export.

Documented outcome

The write-up describes a network that was designed and deployed, with post-cutover validation. It is a client-sized site. It does not claim campus scale or an SLA figure.

Portfolio lab

Multi-Region Azure Hybrid / Zero Trust

A modular Terraform lab for a two-region Azure network, a VPN hub, Bastion access, managed identity, and monitoring hooks.

Objective

Turn hybrid networking and identity practice into code a reviewer can read. The repo is explicit: this is not a live customer or employer deployment, and it is not a claim that this stack ran at nVent.

What I built

  • VNets, subnets, and NSGs in East US 2 and Central US, with peering.
  • Site-to-site VPN, NAT Gateway, Bastion, and a management VM without a public IP.
  • User-assigned managed identity and a custom RBAC role.
  • Log Analytics, a data collection rule, and a VPN metric alert.
  • GitHub Actions checks for format and validate, with no Azure secrets.

Technologies

  • Terraform
  • Azure
  • VNet
  • NSG
  • VPN
  • Bastion
  • Entra ID
  • RBAC
  • Log Analytics
  • GitHub Actions

Key concepts

Workloads have no public IPs. NSGs allow only the next hop that needs access. The VM uses a managed identity instead of a stored secret. Conditional Access and PIM are named as the layer above this RBAC model. The lab does not create them.

Documented outcome

No production outcome is claimed. The documented result is a reviewable lab with fmt and validate in CI, and an honest limit on identity scope.

Portfolio lab

Hybrid Identity Lab — AD DS on Azure VMs

A small Active Directory forest on Azure virtual machines, treated as the source of identity for a hybrid Entra ID design.

Objective

Show the identity work from systems administration — Azure access, Active Directory, Group Policy, and PowerShell — without using an employer directory.

What I built

  • Resource group, virtual network, NSG, and two Windows Server 2022 VMs.
  • Forest bricelab.local with DNS on the domain controller.
  • OU, group, and user baseline, plus a sample Group Policy.
  • Identity hygiene checks for privileged groups, non-expiring passwords, and stale accounts.
  • Written notes on Entra Connect, Cloud Sync, and what not to sync.

Technologies

  • Azure VMs
  • Windows Server
  • AD DS
  • DNS
  • Group Policy
  • PowerShell
  • Entra ID

Key concepts

Role groups instead of a shared Domain Admin habit, a separate Tier 0 admin, and a UPN that is fit to discuss for sync. Password hash sync versus pass-through authentication is explained. It is not connected to a production tenant. MFA is part of that cloud-policy discussion, not a control this repo turns on.

Documented outcome

The lab stands up the on-premises source of authority and a hygiene report. Connecting Entra ID stays conceptual. The repo says this is not an nVent environment and not a production domain.
